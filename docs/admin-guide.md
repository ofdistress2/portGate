# Руководство администратора portGate

Перед установкой скачайте готовый архив Windows x64 по ссылке из [README](../README.md). Для обновления пилотной установки закройте установленную панель, распакуйте новый ZIP отдельно и нажмите «Установить» в новой панели. Подготовьте консольный доступ к серверу на случай восстановления.

## Установка и первый запуск на тестовом сервере

1. Подготовьте снимок ВМ и консольный доступ, сохраните текущие правила.
2. Распакуйте весь архив в отдельную папку. При нажатии «Установить» приложение само копирует файлы по package-manifest.json в `C:\Program Files\KnockGate` и регистрирует службу из этого каталога. Посторонние файлы рабочего стола не копируются. Системное имя службы и её путь сохраняют имя KnockGate для совместимости с пилотной установкой. Обычные пользователи не должны иметь права записи в каталог установки или исполняемые файлы, запускаемые SYSTEM.
3. Запустите `portGate.Manager.exe` с повышением прав либо используйте CLI ниже.
4. Нажмите «Установить». Создаются служба автозапуска и задачи обслуживания; правила RDP на этом шаге не изменяются. При обновлении закройте старую установленную панель и запускайте установку из новой распакованной папки. Каталог `%ProgramData%\KnockGate` сохраняется вместе с клиентами и ключами.
5. В «Настройках» задайте постоянные адреса управления, UDP-порт, внешний IP/DNS сервера для скриптов и сроки. Для суточного допуска выберите «24» и «часов» в окне доступа и задайте максимум не меньше 24 часов. Доступны секунды, минуты, часы, предел — 7 суток. Для listenAddress `::` используется dual-stack IPv4/IPv6.
6. Запустите службу, проверьте план. При конфликте GPO, широких правилах или неопределённой эффективной политике устраните причину. Приложение не переписывает GPO.
7. Нажмите «Применить защиту». Таймер независимого отката — 120 секунд. До отключения прежних правил создаются белый список и UDP-разрешение.
8. Войдите из НОВОГО RDP-сеанса с адреса белого списка, откройте панель в нём и подтвердите. Текущий старый сеанс/консоль не подтверждают доступ. Проверяются тип RDP, новый идентификатор сеанса и ConnectTime WTS после применения. Переподключение в тот же sessionId не принимается: используйте новую сессию. Без подтверждения выполняется откат.
9. После подтверждения создайте персональных клиентов и сохраните скрипты.

Служба принимает авторизацию только при подтверждённой политике и положительной периодической проверке защиты. Проверка выполняется каждые 30 секунд; это не мгновенная защита от изменения политики локальным администратором. При дрейфе прекращается выдача новых допусков; уже выданные истекают/отзываются отдельно.

Проверка политики выполняется в фоне, отдельно от очистки разрешений; обновление панели читает её последний результат. Адрес сервера, стандартное и максимальное окно можно сохранять при активной защите без восстановления правил и перезапуска службы. Стандартное окно подставляется для новых клиентов; у существующего клиента окно меняется через «Изменить имя и срок…». Изменение окна не меняет уже выданное разрешение — новый срок применяется при следующей авторизации. Старые настройки и ключи при обновлении сохраняются.

В течение окна клиент может отключаться и подключаться снова без скрипта, пока его внешний IP тот же. При смене IP требуется новый запуск скрипта. Остановка/перезапуск службы, отзыв ключа или ручной отзыв разрешений закрывают временный допуск досрочно. Окно доступа и срок действия ключа — разные настройки.

## CLI

Из повышенного PowerShell, в каталоге поставки:

```powershell
.\portGate.Host.exe install
.\portGate.Host.exe config
# Сохраните config в свой файл JSON и задайте trustedRdpCidrs.
.\portGate.Host.exe config-save C:\Admin\config.json
.\portGate.Host.exe start
.\portGate.Host.exe plan
.\portGate.Host.exe apply
# В новом RDP-сеансе:
.\portGate.Host.exe confirm
.\portGate.Host.exe clients create 'Ноутбук администратора' 300
.\portGate.Host.exe clients export CLIENT_ID rdp.example.com C:\Admin\Access.bat true
.\portGate.Host.exe clients list
.\portGate.Host.exe clients revoke CLIENT_ID
.\portGate.Host.exe clients rotate CLIENT_ID
.\portGate.Host.exe status
```

Секрет не выводится `clients list`; `clients export` записывает один файл. Экспорт работает и при остановленной службе, после первоначального создания хранилища. В панели диалог сохранения по умолчанию открывает рабочий стол текущей учётной записи; после сохранения показывается полный путь. Повторный экспорт получает тот же ключ, `rotate` создаёт новый и отзывает прежние допуски. `clients edit ID NAME [ISO8601]` меняет имя и срок, пустой срок означает бессрочный.

`--data PATH` переопределяет хранилище. Рабочая установка рассчитана на один экземпляр службы/IPC на компьютер. Коды завершения: 0 — успешно, 1 — ошибка. `help` описывает команды. `plan`/`diagnose` только читают политику.

## Запуск клиентом

Передайте пользователю его `.bat`: основной формат запускается двойным щелчком. Файл содержит настройки, ключ и встроенную PowerShell-логику. Временные `.ps1` не создаются, зависимости не скачиваются. Дополнительный формат `.ps1` предназначен для администраторов; выберите его в диалоге сохранения либо укажите расширение в CLI. Файл является секретным пропуском, его копия имеет те же права. Запуск дополнительного формата из PowerShell:

```powershell
powershell.exe -NoProfile -File .\Access.ps1
# Без запуска mstsc:
powershell.exe -NoProfile -File .\Access.ps1 -NoRdp
```

Не требуется PowerShell 7 или установленный .NET SDK. При политике RemoteSigned скачанному файлу может потребоваться штатное разблокирование после проверки происхождения; при корпоративном запрете запуска обращайтесь к администратору. BAT использует Windows PowerShell 5.1 и не работает при его запрете. Он не меняет ExecutionPolicy и отклоняет Restricted/AllSigned, ConstrainedLanguage и скачанный неподписанный файл при RemoteSigned. Корпоративные ограничения не обходятся. При ошибке окно остаётся открытым до нажатия клавиши; код выхода ненулевой. Ошибки запуска PowerShell показываются дополнительно сообщением на английском языке, не зависящим от кодировки консоли. Клиент возвращает ошибку при отсутствии подписанного подтверждения; «UDP отправлен» не считается успехом.

### Пропуск для macOS

На macOS используется только персональный клиентский скрипт с ключом. Серверная служба и панель работают на Windows Server.

1. При создании клиента или повторном экспорте выберите **macOS** и сохраните персональный файл `.applescript`.
2. На Mac откройте файл в **Редакторе скриптов** и нажмите **«Выполнить» ▶**. Для получения `.scpt` сохраните документ на Mac в формате **«Скрипт»**. Оба файла дают одинаковый доступ, поэтому достаточно передать пользователю один из них.
3. После подтверждения доступа подключитесь установленным RDP-клиентом к адресу и порту, указанным в диалоге.

Клиент Mac использует Foundation и системный `/usr/bin/perl` со стандартными модулями. Ему не требуются Homebrew, Xcode, отдельный конфиг или запуск Terminal. Если системный Perl или его модули отсутствуют, скрипт сообщает об ошибке. Программа с ключом передаётся Perl через поток ввода. Ключ остаётся частью экспортированного файла, включая скомпилированный `.scpt`.

Экспорт для Mac из CLI:

```powershell
.\portGate.Host.exe clients export CLIENT_ID rdp.example.com .\portGate-Access.applescript
```

После авторизации используется тот же IP сервера, с которым выполнен обмен. Клиент перебирает до восьми адресов DNS; поиск имени ограничен пятью секундами, общий обмен — приблизительно 30 секундами с завершением текущей двухсекундной попытки. Порт RDP берётся из подписанного результата. Окно доступа не завершает уже установленный RDP-сеанс. На сервере сохраняются штатные учётные данные и NLA.

## Остановка, восстановление, удаление

```powershell
.\portGate.Host.exe stop
.\portGate.Host.exe restore
.\portGate.Host.exe uninstall --restore
# Либо сохранить только постоянный белый список:
.\portGate.Host.exe uninstall --keep-trusted
```

Штатная остановка удаляет временные разрешения, оставляет белый список. Удаление с сохранением белого списка также удаляет UDP-слушатель и задачи обслуживания. Восстановление возвращает только правила, изменённые portGate; при постороннем изменении исходного правила требуется ручное решение, успешное восстановление не имитируется. Для изменения настроек активной защиты сначала восстановите прежние правила, затем сохраните конфигурацию, перезапустите службу и снова примените план.

## Данные и ограничения

`%ProgramData%\KnockGate`: config.json, состояние с контрольной суммой, XML задач, журнал JSONL с ротацией. Каталог ограничен SYSTEM/Administrators. Ключи защищены DPAPI LocalMachine; резервная копия данных привязана к компьютеру. Для переноса выдайте новые ключи. Контрольная сумма выявляет повреждения, а не защищает от администратора. Журналы не содержат ключей или полных пакетов; экспортированные скрипты не включайте в диагностику.

Firewall-правила не имеют собственного TTL. При падении службы они могут сохраняться до независимой очистки (раз в минуту и при загрузке). При отказе и службы, и планировщика срок может быть превышен. Не заявляется строгая fail-closed гарантия; WFP — отдельное развитие.

Сервер за NAT должен получать UDP-порт авторизации и RDP через корректные внешние правила. Продукт не управляет маршрутизаторами/облачными security groups. Один внешний IP может представлять несколько устройств. Персональный ключ подтверждает право открыть сеть, а не личность пользователя Windows.
