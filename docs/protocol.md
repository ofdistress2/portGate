# portGate UDP protocol v1

Статус: сервер C#, клиенты Windows PowerShell 5.1 и macOS. Начиная с 1.0.10 время проверяется только на сервере.

Одна UDP-датаграмма = одна ASCII-строка без LF, CR, BOM и пробелов. Разделитель `|`. Максимум 1200 байт. Порядок полей фиксированный, дополнительные поля запрещены. Технические ID: `[a-zA-Z0-9_-]{1,64}`. Hex — только нижний регистр. Время — десятичные целые Unix seconds UTC. Ведущие знаки и неканонические числовые форматы не должны использоваться отправителем.

Секрет клиента — 32 случайных байта. Подпись — lowercase hex HMAC-SHA-256 от UTF-8 всех полей перед последним `|`, включая разделители между полями; последний разделитель и сама подпись в MAC не входят. Нет шифрования; ключ по сети не передаётся. Разные типы сообщений разделяют контексты подписей. Подписи проверяются до выдачи challenge/допуска.

```
KG1|HELLO|serverId|clientId|legacyTimestamp|nonce|mac
KG1|CHALLENGE|serverId|clientId|nonce|challenge|challengeExpires|observedIp|mac
KG1|PROOF|serverId|clientId|nonce|challenge|challengeExpires|mac
KG1|RESULT|serverId|clientId|nonce|challenge|leaseExpires|rdpPort|mac
```

nonce и challenge: по 16 случайных байт, hex длиной 32. Сервер получает IP только из UDP endpoint и нормализует IPv4-mapped IPv6. Challenge связан с clientId, nonce, IP и serverId через устойчивую запись и подпись ответа. Смена исходящего порта допустима; смена IP требует нового HELLO. Ответ направляется на endpoint текущего запроса.

Новые клиенты отправляют `0` в поле `legacyTimestamp`. Сервер принимает прежние числовые значения, сохраняя формат и подпись KG1, но не сравнивает их со своими часами. Срок challenge по умолчанию 30 секунд. Сервер определяет его и срок разрешения по собственным часам. Клиенты проверяют подпись и контекст ответа, используют локальные монотонные таймеры для ожидания, а срок разрешения показывают в местном часовом поясе. Запросы с отозванным или просроченным ключом отклоняются. Новые клиенты требуют сервер 1.0.10 или новее.

HELLO повторяет сохранённый CHALLENGE, пока он не использован и не истёк. PROOF повторяет сохранённый RESULT только пока соответствующее разрешение существует. Повтор не продлевает срок. После перезапуска допуски снимаются, RESULT инвалидируется, но nonce хранится до окончания защитного окна. Новый клиентский запуск использует новый nonce.

Кэш хранится до `challengeExpires + 60 секунд`. Повтор HELLO после удаления записи может получить новый случайный challenge, к которому старый PROOF не подходит. Новые nonce при переполнении кэша не принимаются. Лимиты: 200 датаграмм/сек глобально и 20/IP/сек, до 100 клиентов, 2000 записей запросов и 500 временных допусков по умолчанию. Ограничение частоты выполняется до дорогой обработки и не создаёт записи на каждый неизвестный адрес сверх глобального лимита.

Порядок выдачи: устойчивый Prepared → запись правил TCP/UDP → устойчивый Committed и RESULT → отправка RESULT. При сбое применённые частично правила удаляются; очиститель также удаляет Prepared и неизвестные собственные временные правила. Отзыв ключа удаляет только его правила: допуски других клиентов с тем же IP продолжают действовать независимо.

Детерминированный вектор HMAC проверяется тестом RFC 4231 test case 1: ключ `0b` повторён 20 раз, тело `Hi There`, SHA256 MAC `b0344c61d8db38535ca8afceaf0bf12b881dc200c9833da726e9376c2e32cff7`. Сквозной тест генерирует новый ключ и проходит настоящий обмен PowerShell ↔ C# через loopback с MemoryFirewall.

Нельзя заменять новый тип сообщения старым без изменения подписываемого контекста. При последующем расширении формата сохранять KG1 или вводить новую версию с явной совместимостью Windows-скриптов.
