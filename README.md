# portGate

Русский · [English](README.en.md)

portGate ограничивает сетевой доступ к удалённому рабочему столу на Windows Server. В его основе — модификация концепции *port knocking* («стук по портам») с персональным ключом доступа.

Пользователь запускает клиентский скрипт один раз. Скрипт отправляет подписанный запрос, а сервер находит ключ по идентификатору пропуска и присылает одноразовое проверочное число. Скрипт подписывает это число тем же ключом. Так сервер проверяет владение ключом в текущем обмене, а перехваченный ответ из прежнего обмена не открывает новый доступ.

После проверки сервер добавляет временное правило в брандмауэр Windows для новых RDP-подключений с IP-адреса клиента. Правило удаляется по окончании срока доступа. При входе по RDP по-прежнему действуют штатные учётные данные Windows, права доступа и NLA.

- **Сервер и панель управления:** Windows Server 2016, 2019 или 2022, x64. Список целевых платформ и результаты их проверки приведены в [отчёте](docs/validation.md).
- **Пропуск для Windows:** `.bat` или `.ps1` на Windows PowerShell 5.1. **Пропуск для macOS:** персональный `.applescript` или сохранённый из него `.scpt`. Экспортированный файл содержит ключ доступа.
- **Версия 1.0.12:** [скачать portGate для Windows x64](https://github.com/ofdistress2/portGate/releases/latest). Для автономной сборки отдельная установка .NET Runtime не требуется.

## Установка

1. Подготовьте консольный доступ к серверу, снимок ВМ или другой способ восстановить исходные правила.
2. Скачайте и распакуйте весь архив в отдельную папку. Сверьте SHA-256 ZIP с файлом из релиза. Запустите `portGate.Manager.exe` и нажмите **Install** или **Установить**.
3. Задайте постоянные адреса управления и проверьте план. После применения подтвердите доступ из **нового** RDP-сеанса с адреса в списке разрешённых. Если подтверждения нет, portGate запускает автоматический откат.
4. Создайте персональные пропуска и передайте их владельцам по закрытому каналу.

[Руководство администратора](docs/admin-guide.md) описывает обновление, CLI, экспорт пропусков и [восстановление правил](docs/admin-guide.md#остановка-восстановление-удаление). Если служба и планировщик одновременно недоступны, временные правила могут оставаться активными дольше заданного срока.

## Проверка версии

Версия 1.0.11 прошла двухдневный пилот на действующем Windows RDP-сервере. Проверены установка, остановка, перезапуск и откат. Серверная служба развёрнута и работает. Сведения о пилоте и проверках других окружений собраны в [отчёте](docs/validation.md).

## Сборка из исходников

Нужен .NET 10 SDK на Windows. Первое восстановление зависимостей использует NuGet.

```powershell
.\build.ps1
.\build.ps1 -Publish -SelfContained -Package
```

Начиная с 1.0.12, панель открывается на английском. Чтобы переключиться на русский, откройте **Settings** → **Interface language**, выберите **Русский** и нажмите **Apply language**. Выбор сохраняется для текущей учётной записи Windows.

Первая команда собирает решение и запускает штатные тесты, включая UDP loopback на Windows PowerShell 5.1. Вторая также собирает автономный пакет и создаёт ZIP с файлом SHA-256 в папке `publish`. Серверную службу и брандмауэр можно отдельно проверить по [матрице ВМ](docs/vm-acceptance.md).
